# TravelPulse – deployment

TravelPulse estimates the nightly price of an Airbnb listing. It is a FastAPI service with a one-file static frontend, served at `/ui/`.

**Cities covered:** Amsterdam, Barcelona, Berlin, Columbus.

The service can:

- estimate a nightly price for a listing, with an optional calibrated range
- explain which factors drive the estimate
- run what-if scenarios and rank improvements
- flag mispriced listings and summarise neighbourhood markets
- estimate investment yield
- answer free-text questions through an optional advisor
- log the current model's settings, metrics and files to MLflow (optional, see "Experiment tracking")

## Quickstart

From the `deployment/` directory:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app
```

Then open <http://127.0.0.1:8000/ui/>.

The frontend is a single file, `web/index.html`. It has no build step and no framework. It loads Leaflet 1.9.4 and the Plus Jakarta Sans font from CDNs, so the browser needs internet access for the map tiles.

## Endpoints


| Path | Method | Returns | Needs |
|---|---|---|---|
| `/ui/` | GET | The static frontend | Nothing |
| `/predict` | POST | Estimated nightly price | A listing (JSON) |
| `/predict-range` | POST | Lower and upper bounds of the price range (80% interval) | A listing; returns 503 if ranges are not calibrated on this deployment |
| `/explain` | POST | Group effects and top factors behind the estimate | A listing |
| `/whatif` | POST | The estimate before and after a change to the listing | A listing and the changes to apply |
| `/improve` | POST | The changes with the largest predicted gains | A listing |
| `/mispricing` | GET | Listings flagged underpriced, overpriced or fair, filterable by city and flag, with a row limit | `mispriced_listings.csv`; returns 503 without it |
| `/market` | GET | Per-neighbourhood listing count, median price, median occupancy days, median annual revenue and share underpriced, plus an estimate disclaimer | `market_summary.csv`; returns 503 without it |
| `/invest` | POST | Predicted nightly price, occupancy days and source, expected annual revenue, gross and net yield, net revenue, and the assumptions used | A listing, purchase price and annual costs; occupancy override is optional |
| `/advisor` | POST | A text answer about the listing | A question and a listing; returns 503 unless `GEMINI_API_KEY` is set |
| `/seasonality` | GET | Average availability share per city and month (availability proxy, not measured demand) | `seasonality.csv`; returns 503 without it |
| `/parse-listing` | POST | A validated listing JSON filled from a free-text description (Arabic or English) | Text; returns 503 unless `GEMINI_API_KEY` is set |

A listing has these fields: city, latitude, longitude, room type, property type, accommodates, bedrooms, beds, bathrooms, amenities, `host_is_superhost`, `host_identity_verified`, `availability_30`, `number_of_reviews`, `reviews_per_month` and `review_scores_rating`. Errors come back as JSON with a `detail` message, which the frontend shows as-is.

## Model

| Item | Value |
|---|---|
| Algorithm | XGBoost regressor trained on `log1p(price)` |
| Features | 59 |
| Evaluation | Host-disjoint held-out test set |
| MAE | $41.36 |
| RMSE | $60.91 |
| R² | 0.759 |

These numbers come from the modeling notebook. Tests enforce parity between the service and the notebook.

### How to read the outputs

Treat every output as an estimate:

- The data is a **single scrape snapshot (Sep–Oct 2026)**.
- The calendar data has **no daily prices**.
- Weather features use a **reference year**, not the actual year of each stay.
- Mispricing flags, market summaries and investment figures inherit all of the above. They are not forecasts or guarantees.

## Advisor

The advisor is **disabled unless `GEMINI_API_KEY` is set**. You can optionally set `GEMINI_MODEL` to choose the model.

```bash
export GEMINI_API_KEY=your-key
export GEMINI_MODEL=your-model-name   # optional
uvicorn app.main:app

```

When enabled, the question and the listing you submit are sent to the Gemini API to produce the answer. Nothing is sent anywhere else. Without a key, `/advisor` returns 503 and the UI says the advisor is disabled.

## Data files

`mispriced_listings.csv` and `market_summary.csv` are generated by the analysis scripts. They are not produced by the API itself.

- Without `mispriced_listings.csv`, `/mispricing` returns 503 and the Mispricing tab shows "Mispricing data is not published on this deployment yet."
- Without `market_summary.csv`, `/market` returns 503 and the Market tab shows a not-published message.
- Re-run the analysis scripts to refresh these files after the underlying data changes.

## Experiment tracking (MLflow)

MLflow is a tool that keeps a notebook of your model runs: for each run it stores the settings (params), the quality numbers (metrics) and the saved files (artifacts). You open a web page and compare runs side by side.

`tools/log_to_mlflow.py` logs the model that is already in `models/`. It is optional and the site does not need it.

```bash
pip install -r requirements-mlflow.txt
python -m tools.log_to_mlflow
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

Then open <http://127.0.0.1:5000>, click the `travelpulse-price-model` experiment and then a run.

What a run contains:

- **Params:** algorithm, number of features, number of trees, reference date, training price range, calibration rows.
- **Metrics:** MAE, RMSE and R² (copied from the modeling notebook, not recomputed) and the 80% / 90% interval widths.
- **Artifacts:** `xgb_model.json`, `artifacts.json` and the model in MLflow's own format.

What it does **not** do:

- It does **not train a model.** Each run logs the same existing model. You will only see different numbers after you retrain in the notebook, update `NOTEBOOK_METRICS` in the script and log again.
- It does not change the API or the site.

The local files `mlflow.db`, `mlruns/` and `mlartifacts/` are in `.gitignore`; do not commit them.
